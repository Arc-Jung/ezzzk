# 변경 이력

### 2026-11-14

- **채팅 오버레이 하단 여백 옵션** — 설정 → 채팅에서 ‘하단 빈 공간에 표시’를 켜면 영상 아래 검은 여백에 채팅을 표시한다(기본 꺼짐). 최소 3줄이 들어갈 공간을 확보하고 볼륨·재생 조작부를 피한다. 여백이 부족하면 영상 위의 기존 위치로 돌아온다.

- **오버레이에서 채팅 보내기** — 오른쪽 아래 말풍선을 누르면 작은 채팅 입력창이 열린다. 전체화면에서도 사용할 수 있고, 멀티뷰에서는 누른 방송의 채팅방으로 전송한다. 채팅이 없는 상태에서도 말풍선을 표시한다.

- **더블 클릭으로 전체화면 전환** — 영상의 두 번 터치로 켜거나 끄도록 변경했다. 옵션 이름도 변경했으며 기본 켜짐과 기존 ON/OFF 설정은 유지한다.

### 2026-11-12

- **세 번 터치로 전체화면 전환** — 영상의 같은 곳을 빠르게 세 번 누르면 전체화면을 켜거나 끈다. 싱글뷰와 멀티뷰에서 동작하며, 채팅·설정 조작과 스와이프·핀치 확대는 제외한다. 재생 설정과 확장 팝업에서 켜고 끌 수 있다(기본 켜짐).

### 2026-11-10

- **자동 PiP 옵션 추가** — 재생 설정과 확장 팝업에서 켜고 끌 수 있다(기본 끄기). 지원 브라우저가 자동 PiP 액션을 전달하면 재생 중인 싱글뷰 영상을 전환한다. 광고·멀티뷰·일시정지·종료 영상은 제외하고, PiP 중에는 전체화면으로 다시 끌어오지 않는다. 브라우저 자체의 전체화면 → 홈 PiP는 별도로 동작한다.

### 2026-11-08

### 2026-10-19

### 2026-09-03

- **치지직 내장 클린봇 자동 끄기를 기본 끄기로 변경** — 확장이 기본값으로 네이버 계정 설정을 바꾸는 동작이라 크롬 웹스토어 심사에서 문제가 될 수 있다. 쓰려면 설정에서 직접 켠다 (통나무 자동 수집은 이전부터 기본 끄기다)

### 2026-08-27

- **볼륨 `−`/`+`(와 `Shift + ↑`/`Shift + ↓`)로 조절하면 음소거를 먼저 푼다** — 예전에는 음소거 상태에서 볼륨을 올려도 숫자만 올라가고 소리는 나지 않았다. 음소거 자동 해제를 꺼 둔 경우에도 직접 조절한 것은 사용자의 명시적 의사이므로 똑같이 해제한다
- **멀티뷰에서 음소거 자동 해제가 걸리지 않던 문제 수정** — 원인은 두 가지였다. ① 자동 해제가 **2회 실패하면 그 페이지에서 영구 포기**했고, 초기 적용 이후에는 플레이어가 스스로 다시 음소거해도 아무도 다시 보지 않았다(슬롯은 전역 저장값을 쓰지 않아 호스트가 남긴 음소거 상태를 물려받는다). 이제 지수 백오프로 재시도하고, 자동 재시도를 다 쓰면 포기하는 대신 **다음 사용자 조작에서 다시 시도**한다. ② "사용자가 직접 음소거했는가" 판정이 브라우저 활성화 플래그 하나에 기대고 있었는데, **우리 자동재생 폴백이 재생 버튼을 대신 누르는 순간 그 플래그가 켜져** 자동 해제가 매번 "사용자가 한 것"으로 오판됐다(실측 2026-08-27 — 슬롯에서 재시도가 한 번도 걸리지 않은 직접 원인). 실제 입력 이벤트를 함께 확인하도록 고쳤다
- **슬롯 사이 사용자 조작 중계** — 멀티뷰는 슬롯마다 프레임이 달라 사용자가 슬롯 하나를 눌러도 나머지 슬롯에는 그 조작이 전달되지 않는다. 자동재생 정책 때문에 음소거로 시작한 슬롯이 계속 음소거로 남던 경로라, 스테이지가 자기 프레임의 조작을 모든 슬롯에 알려 재시도를 깨운다
- 멀티뷰가 열려 있는 동안 **원본(호스트) 플레이어는 자동 해제 대상에서 제외**한다 — 슬롯 소리 위에 원본 소리가 겹치지 않게 하려는 기존 동작과 충돌하지 않기 위함

### 2026-08-24

- **멀티뷰 진입 시 슬롯 4개를 한꺼번에 요청하지 않고 100ms 간격으로 나눠 로드** — 예전에는 4개 iframe 의 주소를 같은 순간에 대입해 치지직 페이지 4벌이 동시에 출발했다. 순서대로 100ms 씩 벌려 출발시킨다(마지막 슬롯이 300ms 늦게 시작할 뿐이라 체감 지연은 없다). 로드 대기 시간도 각 슬롯이 **실제로 출발한 시점부터** 세므로 뒤쪽 슬롯이 손해 보지 않는다
- **재생이 시작되지 않는 슬롯에 안내 표시** — 방송이 끝났거나 로그인·연령 확인이 필요한 방송이면 슬롯이 **검은 칸으로만 남고 아무 설명이 없었다**(실측 2026-08-24: 4슬롯 중 1칸). 프레임 자체는 정상 로드돼 기존 실패 경로에 걸리지 않던 상태다. 10초 넘게 재생이 시작되지 않으면 이유 후보를 적은 안내를 슬롯 위에 띄운다
- **팔로우 채널 목록이 일부만 나오던 문제 수정** — 팔로우 목록을 **한 번만** 요청해 서버 기본 페이지 크기까지만 받았다. 이제 끝까지 넘겨 받아 합친다(중복 제거 포함)
- **채팅 폭 조절 `+`/`−` 클릭당 이동폭 축소 (기본 5% → 2%)** — 한 번 클릭에 너무 크게 움직인다는 사용자 보고. 설정에서 고를 수 있는 단위에도 2%를 추가했다(1/2/5/10%)
- **멀티뷰를 쓴 뒤 음소거가 되던 문제 수정** — 치지직이 볼륨·음소거 상태를 저장하는 `localStorage` 는 origin 전체(호스트 페이지 + 모든 슬롯 iframe)가 공유하는데, 슬롯도 같은 볼륨 기능이 도는 탓에 슬롯의 일시적 상태(특히 자동재생 차단 시 강제 음소거)가 이 전역 값을 덮어써 멀티뷰를 나간 뒤(또는 다음 새로고침) 원래 방송이 음소거로 시작하는 경우가 있었다. 슬롯 프레임은 이 전역 저장을 하지 않도록 수정
